### BG-0001: Unable to recover correct route after returning to junction
- **Category**: navigation
- **Severity**: high
- **Status Change**: `REOPENED → FIXED`
- **Root Cause Analysis**:
  1. `updateNavigationRouteChoice` in `src/main.js` only checked `currentRouteId === junction.incomingRouteId` for junction decision mode. When returning along an outgoing branch (`route-0-branch-left`), `currentRouteId` was the branch ID, so junction candidate selection and driver guidance evaluation were completely skipped during approach.
  2. Upon reaching `Math.abs(delta) <= 8`, the previous fix forcibly reset `navigationState.currentRouteId = junction.incomingRouteId` and `isOnWrongRoute = false` immediately at the junction hub node. This cleared `isOnWrongRoute` prematurely before the player had chosen or committed to the correct branch.
  3. When `currentRouteId` became `junction.incomingRouteId` (`route-0-trunk`), the cart traveling toward start had negative `delta`, making `delta >= BRANCH_COMMIT_DISTANCE` impossible to satisfy, so commitment to the correct outgoing route never occurred.

- **Fix Implemented**:
  1. Updated `updateNavigationRouteChoice` to recognize both First Arrival (`currentRouteId === junction.incomingRouteId`) and Return Arrival (`isCurrentBranch && Math.abs(delta) <= JUNCTION_APPROACH_DISTANCE + 8`).
  2. On Return Arrival, stale branch commitment (`branchCommitted = false`, `committedRouteId = "None"`) and old latched player guidance (`driverInputAge > 10`) are cleared, allowing fresh driver guidance (Left/Right/Straight) and natural candidate selection to actively steer the bulls toward the player's chosen branch.
  3. `navigationState.isOnWrongRoute` remains `true` during the return approach and junction decision phase, and transitions to `false` ONLY when the cart commits to the correct outgoing route (`chosenRouteId === junction.correctOutgoingRouteId`).
  4. Preserved all wrong-route gameplay, natural bull choices, road containment, and villager guidance dialogue.
