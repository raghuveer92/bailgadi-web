## Resolved Issues

### BG-0001: Unable to recover correct route after returning to junction
- **Category**: navigation
- **Severity**: high
- **Status Change**: `REOPENED → FIXED`
- **Root Cause Analysis**:
  1. `applyNavigationRouteSample` in `src/main.js` only checked `navigationState.currentRouteId === junction.incomingRouteId` when assigning `sharedJunction`.
  2. When a cart returned to the junction hub from an outgoing branch (`route-0-branch-left`), `currentRouteId` was `"route-0-branch-left"`, so `sharedJunction` remained `null`.
  3. Because `sharedJunction` remained `null`, `applySharedJunctionSurface` was skipped during return arrival. The road model sampled the cart against a single narrow branch corridor instead of the wide shared junction hub. When the cart turned to recover onto the correct branch, road physics containment forces pushed the cart off into the side ditch/wall.

- **Fix Implemented**:
  1. Restored `isFirstArrival` commit trigger in `updateNavigationRouteChoice` to standard `delta >= BRANCH_COMMIT_DISTANCE`.
  2. Updated `applyNavigationRouteSample` to assign `sharedJunction` when `isIncoming` OR `isOutgoingBranch` (`routeDirectionForId(junction, currentRouteId) !== "NONE"`) is active while cart distance is within the junction zone (`delta >= -ROUTE_CHOICE_DISTANCE && delta < BRANCH_COMMIT_MAX_DISTANCE`).
  3. This ensures `applySharedJunctionSurface` creates a wide, smooth junction surface whenever a cart re-enters the junction area from an outgoing branch, allowing smooth turning and alignment onto the correct outgoing route.
