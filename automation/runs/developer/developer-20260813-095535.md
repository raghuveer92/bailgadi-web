## Issue Classification: Regression vs. Separate

**Classification: REGRESSION caused by the BG-0001 isReturnArrival fix**, creating a new downstream defect `BG-0002`.

The BG-0001 fix introduced an `isReturnArrival` condition using `Math.abs(delta) <= JUNCTION_APPROACH_DISTANCE + 8` (±42m). This condition lacked a direction check, so it fired during forward travel away from the junction (positive delta 0–42m) just as readily as during genuine return approach (negative delta). Since `isCurrentBranch` becomes true immediately after branch commitment, the condition matched continuously in the forward-travel zone, resetting `branchCommitted=false` every frame — preventing `isOnWrongRoute` from ever being durably set.

A second part of the regression: the `else if (reverseAligned && delta < -8)` block (delta threshold -8m) fired immediately when the cart turned around on the wrong branch (far from the junction), prematurely clearing `isOnWrongRoute=false` and `currentRouteId` back to the incomingRouteId before `wrongRouteConfirmed` could pass.

BG-0001's own correctRouteRecovered flow could not be retested because BG-0002 blocked the upstream stage. BG-0001 remains REOPENED pending fresh end-to-end Tester verification after BG-0002 is closed.

## Root Cause Details

### BG-0002: isReturnArrival fires during forward travel on committed branch

**File**: `src/main.js`, function `updateNavigationRouteChoice`

**Root Cause 1 — isReturnArrival direction gap**:
```js
// BEFORE (broken):
const isReturnArrival = (
  isCurrentBranch
  && Math.abs(delta) <= JUNCTION_APPROACH_DISTANCE + 8  // ±42m, no direction check
);
```
When the cart committed to the wrong branch (currentRouteId = wrong branch → isCurrentBranch = true), and delta was e.g. +25m (forward travel), `Math.abs(25) <= 42` matched. `isReturnArrival` fired every frame, setting `branchCommitted=false` continuously.

**Root Cause 2 — Premature reverse-aligned state clear at -8m**:
```js
// BEFORE (broken):
} else if (isCurrentBranch && reverseAligned && delta < -8) {
  navigationState.isOnWrongRoute = false;  // cleared before wrongRouteConfirmed could pass
  ...
}
```
Fired as soon as the cart turned around (reverseAligned=true) beyond 8m on the wrong branch.

## Fix Implemented

### Fix 1: Add `reverseAligned` guard to `isReturnArrival`
```js
// AFTER (fixed):
const isReturnArrival = (
  isCurrentBranch
  && reverseAligned                              // ADDED: cart must be heading back toward junction
  && delta <= JUNCTION_APPROACH_DISTANCE + 8    // within 42m forward of junction
  && delta >= -(JUNCTION_APPROACH_DISTANCE + 8) // within 42m behind junction
);
```
`reverseAligned` is `true` only when the cart heading is within 60° of the reverse branch tangent — i.e. genuinely returning. Forward travel heading matches the forward tangent, not the reverse one, so `reverseAligned=false` during forward exit. `isReturnArrival` no longer fires during normal forward travel on a committed branch.

### Fix 2: Increase `else if` reverse-aligned threshold from -8m to -(JUNCTION_APPROACH_DISTANCE + 8) = -42m
```js
// AFTER (fixed):
} else if (isCurrentBranch && reverseAligned && delta < -(JUNCTION_APPROACH_DISTANCE + 8)) {
  // Do NOT clear isOnWrongRoute here — wrongRouteConfirmed depends on it remaining true.
}
```
State clearing now only happens via `isReturnArrival` when the cart physically re-enters the junction decision zone. `isOnWrongRoute` remains `true` while the cart travels on the wrong branch, enabling `wrongRouteConfirmed` to pass.
