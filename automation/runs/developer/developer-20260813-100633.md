## Root Cause: Exact Point Where Re-Commit Chain Was Failing

The re-commit chain (`returnedToJunction → correctRouteRecovered`) broke at the gap between two phases:

**Phase 1 — Return approach (reverseAligned=true):**
- `isReturnArrival` fires every frame while cart is in junction zone heading backward
- `branchCommitted=false` was reset on **every** frame (not once), so any successful `clearlyOnBranch` was immediately undone the next frame
- But `clearlyOnBranch` couldn't fire anyway: `headingDifference` = angle(cart heading ≈ toward junction, outgoing branch forward tangent) ≈ 180° >> `BRANCH_COMMIT_HEADING_LIMIT=68°`. Commit geometrically impossible while facing backward.

**Phase 2 — Forward departure (reverseAligned=false, cart turns to face correct branch):**
- `reverseAligned` becomes false as cart turns
- `isReturnArrival = false` (requires reverseAligned)
- `isFirstArrival = false` (requires `currentRouteId === incomingRouteId`; it's still the wrong branch)
- **Neither condition fires** — the commit loop is completely inactive
- The cart physically enters the correct branch corridor. `clearlyOnBranch` would pass. But it's never evaluated.
- `isOnWrongRoute` stays `true` indefinitely → `correctRouteRecovered` times out

## Fix Implemented

**File**: `src/main.js`

### 1. Added `returnReentryActive` and `returnReentryJunctionId` to `navigationState`

Two new fields on the navigation state object initialized to `false` / `"None"`.

### 2. `isReturnArrival` — first-frame-only commitment clear

```js
// BEFORE: cleared branchCommitted on EVERY frame of isReturnArrival
if (isReturnArrival) {
  navigationState.branchCommitted = false;  // reset every frame — fatal
  ...
}

// AFTER: clear once on first frame only, set flag
if (isReturnArrival && !navigationState.returnReentryActive) {
  navigationState.branchCommitted = false;  // cleared exactly once
  navigationState.returnReentryActive = true;
  navigationState.returnReentryJunctionId = junction.id;
  ...
}
```

### 3. New `isReturnDeparture` condition — fills the gap

```js
const isReturnDeparture = (
  navigationState.returnReentryActive             // flag set by isReturnArrival
  && navigationState.returnReentryJunctionId === junction.id
  && !reverseAligned                              // cart now facing forward (toward outgoing branch)
  && !navigationState.branchCommitted             // not yet committed
  && Math.abs(delta) <= JUNCTION_APPROACH_DISTANCE + 8  // still in junction zone
);
```

When the cart turns and faces the correct branch, `isReturnDeparture=true`. The commit loop runs with heading now aligned with the outgoing branch. `clearlyOnBranch` passes. Cart commits to correct route.

### 4. Commit success clears the flag

```js
if (clearlyOnBranch) {
  ...
  navigationState.returnReentryActive = false;
  navigationState.returnReentryJunctionId = "None";
  ...
}
```

### 5. Stale-guard after junction loop

```js
if (navigationState.returnReentryActive && nearbyJunctionIndex < 0) {
  navigationState.returnReentryActive = false;
  navigationState.returnReentryJunctionId = "None";
}
```

Prevents the flag persisting if the cart exits the junction zone without committing.
