## Architectural Conflict
The previous BG-0001 fix (`returnReentryActive`) clashed fatally with BG-0002 because both relied on overlapping absolute distance checks (`isReturnArrival`). 
- BG-0002 requires that when the cart is travelling forward on a committed wrong branch away from the junction, its commitment stays stable (even if it is still within 42m of the junction).
- BG-0001 requires that when the cart is returning backward on a wrong branch toward the junction, its commitment must be cleared to allow re-entry.

Because distance (`Math.abs(delta)`) was used without robustly distinguishing "forward travel away" from "backward travel toward", the BG-0001 fix caused the junction to continually re-evaluate during the initial forward departure phase of the wrong branch, clearing the commitment prematurely and re-breaking BG-0002.

## Fix Implemented: Explicit Junction Lifecycle

To resolve the conflict, the implicit, overlapping condition checks in `updateNavigationRouteChoice` were replaced with an explicit state machine inside `navigationState`:

**`junctionLifecycleState` States:**
- `NONE`: Cart is not near any junction.
- `DECIDING`: Cart is in the junction approach zone and selecting a branch. This state handles both the first arrival AND return re-entry.
- `COMMITTED`: A branch has been chosen, and the cart is departing. **No junction decision logic runs during this phase**, ensuring BG-0002 stability.
- `RETURNING`: The cart was on a committed branch but reversed its physical motion and heading to face back toward the active junction.

### State Transitions

1. **`NONE` → `DECIDING` (First Approach)**
   Triggers when approaching a junction on its incoming route. The old branch commitment is cleared if a new junction is selected.

2. **`DECIDING` → `COMMITTED`**
   Triggers when the cart aligns with an outgoing branch (`clearlyOnBranch` passes). `isOnWrongRoute` is evaluated and latched. `activeLifecycleJunctionId` remains set.

3. **`COMMITTED` → `RETURNING` (Turnaround)**
   Triggers ONLY when three conditions are met simultaneously:
   - Cart is on the committed outgoing branch.
   - Cart heading is reversed (aligned back toward junction).
   - **Cart is physically moving backward** (using `frameMotion = physicalRouteDistance - lastPhysicalRouteDistance < 0`).
   
   This strict check ensures that forward travel immediately after commit (BG-0002) NEVER triggers the return logic.

4. **`RETURNING` → `DECIDING` (Return Re-entry)**
   Triggers when the returning cart physically crosses back into the junction approach zone.
   - Old branch commitment is cleared **exactly once**.
   - State switches back to `DECIDING`, opening the commit window for the explicit player guidance to select the correct outgoing route (BG-0001).

### Shared Junction Surface
The existing `applyNavigationRouteSample` logic checks `!navigationState.branchCommitted` to activate the shared junction surface. Since `branchCommitted` correctly reflects the `DECIDING` and `COMMITTED` lifecycle phases, the shared surface correctly activates during return re-entry (allowing smooth turning across branches) and deactivates once the new correct branch is committed.
