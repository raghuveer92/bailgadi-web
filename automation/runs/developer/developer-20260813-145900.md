## ISSUE RESOLUTION SUMMARY

### 1. BG-0001: Unable to recover correct route after returning to junction
- **Severity**: HIGH
- **Status Transition**: `REOPENED → FIXED`
- **Subsystem**: Navigation / Wrong-Route Return & Road Guidance
- **Root Cause Analysis**:
  During wrong-route return travel and junction re-entry (after the player turns the cart around 180° to return to the junction), `updateStableRoadHeading` in `src/main.js` was sampling `currentRoadSample.routeDistance + lookAheadDistance` unconditionally.
  Because branch route distance increases when moving away from the junction, sampling `+lookAheadDistance` while facing backward caused the guidance look-ahead to sample a point **behind** the cart's direction of travel (further down the wrong branch).
  Consequently, `sampledHeading` was calculated pointing away from the junction (180° mismatch with travel direction), causing bull guidance to fight the return movement and route recovery steering, resulting in `correctRouteRecovered` timing out.
- **Correction Implemented**:
  In `src/main.js` (`updateStableRoadHeading`), added an orientation-aware look-ahead calculation:
  ```javascript
  const reverseRoadHeading = Math.atan2(
    Math.sin(state.roadHeading + Math.PI),
    Math.cos(state.roadHeading + Math.PI),
  );
  const facingReverse = Math.abs(wrappedAngleDelta(state.heading, reverseRoadHeading))
    < Math.abs(wrappedAngleDelta(state.heading, state.roadHeading));
  const signedLookAhead = facingReverse ? -lookAheadDistance : lookAheadDistance;
  ```
  `sampleBaseRouteDistance` now receives `currentRoadSample.routeDistance + signedLookAhead`, ensuring the look-ahead point is always placed in front of the cart along its actual vector of travel (towards the junction when `facingReverse === true`).
